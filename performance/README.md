## Подготовка

1. На стенде с установленным приложением создайте Проект по процессу "Разработка по требованию" с использованием демо данных.
2. Заполните `.env` значениями стенда.

```
git clone https://github.com/devprom-dev/docker.git
cd docker/performance
vi .env
```

## Переменные (`.env`)

| Переменная | Описание |
|---|---|
| `devprom_auth_key` | Api ключ пользователя (создателя Проекта), Профиль пользователя - Ключи |
| `base_url` | Домен стенда (без `http://` или `https://`) |
| `port_number` | Порт стенда |
| `number_of_threads` | Максимальное кол-во пользователей |
| `project_codename` | Кодовое имя проекта по процессу "Разработка по требованиям" |
| `task_id` | ID задачи у которой будет списываться время, можно взять из карточки задачи, вкладка Дополнительно, API-ссылка, число в конце URL |
| `user_id` | ID пользователя для которого будет списываться время (создателя Проекта) |
| `requirement_id` | ID требования (корневой узел, без родителей!), можно взять из карточки требования, вкладка Дополнительно, API-ссылка, число в конце URL |
| `task_type` | ID типа задачи, можно взять из карточки типа задачи (справочник Типы задач), вкладка Дополнительно, API-ссылка, число в конце URL |

Не указывайте протокол в `base_url`: нужно `stand.example.com`, а не `https://stand.example.com`.

## Запуск

```
docker compose up --abort-on-container-exit --exit-code-from jmeter
```

После старта Docker скачает образ `alpine/jmeter:5.6.3` (при первом запуске) и выполнит тест в non-GUI режиме. Дождитесь завершения прогона.

## Результаты
В процессе нагрузочного тестирования в консоли будут выводиться промежуточные результаты. Нагрузку (количество пользователей) необходимо постепенно повышать до появления ошибок в столбце Err.
Если ошибки начали появляться при минимальной нагрузке, значит есть проблемы с входными параметрами (task_id, user_id, requirement_id, task_type и т.п.), сперва необходимо их устранить.
Причины ошибок будут отображаться в отчете в каталоге results.

Количество пользователей, при котором начинаются появляться ошибки, связанные с превышением таймаутов, является максимальным количеством одновременно работающих пользователей на данной конфигурации сервера.
Для оценки общего количества пользователей, комфортно работающих на данной конфигурации сервера, необходимо разделить полученное число на 0.3

После завершения прогона в каталоге `results/` можно найти подробные отчеты о ходе нагрузочного тестирования:

| Файл / каталог | Содержимое |
|---|---|
| `results/log.jtl` | Сырые результаты сэмплов |
| `results/jmeter.log` | Лог JMeter |
| `results/report/index.html` | HTML-отчёт (Dashboard) |
